NLP Foundations — demonstration course
This original teaching sample was written for this project. It is a tiny demonstration corpus, not a complete NLP curriculum or an external benchmark.

1. Text preprocessing
Natural language processing studies computational methods for working with human language. A corpus is a collection of documents. Preprocessing prepares raw text for a downstream task. Tokenization splits text into units such as words, subwords, or characters. A tokenizer must handle punctuation, contractions, and language-specific conventions. Lowercasing can reduce vocabulary size but may remove distinctions between proper names and common words. Stop-word removal discards frequent function words, but these words can matter for negation or question answering. Lemmatization maps inflected words to a dictionary base form using linguistic information. Stemming applies heuristic rules to shorten words and may produce forms that are not valid dictionary entries. Preprocessing choices should be evaluated for the target task rather than applied mechanically. Retaining page numbers and document titles allows users to trace extracted text to the original course material. Scanned PDFs contain page images and generally require optical character recognition before a text extraction tool can read them. A training corpus should be separated from a held-out evaluation corpus before fitting data-dependent preprocessing steps. Otherwise information from the evaluation set can leak into model development and produce optimistic results.

2. Representing text
TF-IDF stands for term frequency–inverse document frequency. It represents a document as a sparse vector over a vocabulary. Term frequency captures how often a term occurs in a document. Inverse document frequency gives less weight to terms that occur in many documents. Cosine similarity measures the angle between vectors by dividing their dot product by the product of their lengths. A cosine score is a similarity measure, not a calibrated probability of correctness. TF-IDF retrieval is a useful lexical baseline, but it may miss paraphrases that use different vocabulary. Dense embeddings represent text as continuous vectors learned by a model. Semantically related passages may have nearby embedding vectors even when they share few exact words. The embedding model must support the language of the corpus. Index documents and user questions with compatible representations. Normalizing vectors to unit length makes their dot product equal to cosine similarity. Exact vector search compares a query with every indexed passage. Approximate nearest-neighbor search trades some retrieval accuracy for lower search costs on large collections. Evaluation should compare methods on the same corpus, questions, and relevance judgments.

3. Retrieval-augmented generation
Retrieval-augmented generation, abbreviated RAG, combines document retrieval with language-model generation. The indexing pipeline extracts text, splits it into passages, computes representations, and stores vectors with source metadata. At question time, a retriever selects relevant passages. The language model receives the question and retrieved evidence, then produces an answer. Chunk size controls how much text a passage contains. Small chunks can isolate facts but lose surrounding context. Large chunks provide context but can dilute retrieval precision and consume more of the model context window. Chunk overlap repeats a small amount of text between neighboring passages to preserve continuity. A top-k setting limits how many passages are passed to the generator. Increasing k can improve coverage but may introduce unrelated evidence. RAG does not guarantee factual accuracy. A generator can misinterpret correct evidence or use unsupported background knowledge. An answer should cite the passages supporting its claims. If evidence is missing, the assistant should state that it cannot answer from the course. Instructions embedded in retrieved documents must be treated as document content rather than executable commands. A citation that points to a real passage is necessary for traceability, but its existence alone does not prove that the passage supports every claim.

4. Summarization and assessment
Extractive summarization selects material from the original document. Abstractive summarization generates a new condensed formulation. A useful study summary preserves key definitions, relationships, and qualifications while avoiding invented facts. For a document longer than the model context window, map-reduce summarization first summarizes batches of passages and then combines the intermediate notes. Each intermediate note should preserve source references. Multiple-choice questions need a clear question, one correct answer, and plausible but incorrect distractors. Difficulty can vary from recalling a definition to applying a concept in a new example. Corrections should include an explanation and supporting evidence from the course. Automatic checks can verify that options are distinct, the answer index is valid, and a quoted passage actually occurs in the source. These structural checks do not establish that the question is pedagogically sound. A human reviewer should check correctness, ambiguity, difficulty, and the quality of distractors. Small corpora may not support many distinct questions.

5. Evaluation
Retrieval recall at k measures whether relevant evidence appears among the first k retrieved passages. Mean reciprocal rank averages the reciprocal rank of the first relevant result. Relevance judgments should be prepared independently of the retrieval output. Evaluation questions should include direct factual questions, paraphrases, ambiguous questions, and questions outside the corpus. An unanswerable question should trigger an explicit statement that evidence is insufficient. Answer evaluation should consider correctness, evidence support, citation accuracy, and clarity separately. Summary evaluation should consider fidelity, coverage, concision, and readability. Quiz evaluation should examine correctness, answer uniqueness, explanation quality, and difficulty. Latency measures elapsed time for an operation. Experiments should record model names, corpus version, chunk size, overlap, retrieval method, and top-k. A tiny demonstration set is useful for regression checks, but its scores do not establish general performance on real university courses.
